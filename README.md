# PulseCommerce AI

**Autonomous Multi-Tenant Retail Intelligence & Inventory Operations Platform**

> Submitted for **AMD Developer Hackathon ACT III · Track 3 (Reinvent Commerce)**  
> Competing for the **Google (Gemma) Prize Track** and the **Evolus Prize Track**

---

## Overview

Global retail loses over $1.2 trillion annually to stockouts and overstocked inventory. Small and medium merchants face an impossible balancing act: tying up working capital in stagnant stock or losing customer goodwill when bestsellers sell out.

**PulseCommerce AI** solves this dilemma through a dual-engine architecture:
1. **Deterministic Classical Machine Learning**: Strictly compliant with Track 3 rules, an audited statistical model (`HistGradientBoostingRegressor`) predicts multi-horizon unit demand with a **12.4% WAPE** (Weighted Absolute Percentage Error), outperforming seasonal and moving-average baselines by up to 21.6%.
2. **Agentic Reasoning & Negotiation (Google Gemma 4 on AMD Instinct GPUs)**: Rather than letting an LLM generate ungrounded financial predictions, Gemma 4 is deployed specifically for contextual reasoning, policy interpretation, supplier purchase order drafting, promotional markdown copy generation, and human-in-the-loop decision gating.
3. **Multi-Agent Orchestration (Evolus)**: Coordinates knowledge retrieval, business-specific constraints, and audited tool executions.
4. **Model Context Protocol (MCP) ERP Ledger**: Executes cryptographically verified purchase orders and pricing adjustments directly into an enterprise audit trail.

---

## Key Differentiators & Hackathon Track Alignment

### Track 3 Rule Compliance (Reinvent Commerce)
The Track 3 rules explicitly forbid using raw LLMs for demand forecasting due to hallucination risks and mathematical drift. PulseCommerce AI enforces a strict boundary:
- **Forecast Engine**: 100% deterministic Python/Scikit-Learn pipeline.
- **Agent Reasoning**: Google Gemma 4 acts as an executive copilot that explains model outputs, audits supplier constraints, and drafts actionable communications.

### Google (Gemma) Prize Track
- Powered by **Google Gemma 4** (`google/gemma-4-31B-it` or `gemma-4-26b-a4b-it`) hosted via OpenAI-compatible vLLM endpoints on AMD Instinct infrastructure or Google AI Studio.
- Grounded system prompts instruct Gemma 4 never to alter mathematical figures generated by the forecast model.
- Generates vendor purchase orders with exact MOQs, lead times, and terms, alongside high-converting promotional markdown campaigns.

### Evolus Prize Track
- Integrates with **Evolus Cloud** (`app.evolus.ai`) using 5 modular building blocks:
  1. Custom Model Endpoint (AMD vLLM integration).
  2. Knowledge Library (Multi-tenant supplier rules and margin limits).
  3. Multi-Step Pipeline (Ingestion -> Forecasting -> Contextualization -> Reasoning -> Approval -> MCP Execution).
  4. Human-in-the-Loop Gatekeeper (Store manager approval interface).
  5. MCP Connector (Automated ERP tool invocation).

## Empirical Benchmark Results

Evaluated via a rolling-origin temporal backtest across 4 evaluation windows (weeks 104, 116, 128, 140) on retail weekly sales:

| Model / Approach | WAPE (%) | Relative Accuracy Gain | Purpose |
| :--- | :---: | :---: | :--- |
| **Seasonal Naive** (Same week prior year) | 15.9% | Baseline | Historical baseline |
| **Moving Average** (4-week rolling mean) | 13.5% | +15.1% vs Naive | Short-term trend baseline |
| **HistGradientBoosting (Ours)** | **12.4%** | **+7.9% vs Moving Avg** (+21.6% vs Naive) | **Production demand forecaster** |

All backtest metrics are reproducible via `python src/backtest.py`. For real-world datasets (Kaggle M5 Forecasting or UCI Online Retail II), run `python src/load_real_data.py --csv <path>`.

## User Interface & Design System

The application features a modern web interface inspired by the warm editorial design language of AstralWeb.net:

- **Typography**: Paired Google Fonts `Source Serif 4` (high-contrast editorial headings) with `Inter` (data and UI typography).

  - Ink Charcoal (`#17191c`) high-contrast text.
  - Rust Accent (`#5d2a1a`) for brand identity.
  - Mint Emerald (`#55db9c`) for stock health and status indicators.
  - Sky Wash (`#d3e3fc`) and Apricot Wash (`#fbe1d1`) for visual separation.
- **Hero & Assembly Window**: Soft dawn radial lighting backdrop with 4 floating metric chips tilted at natural angles (`-4deg`, `+3deg`) surrounding an interactive glassmorphic application window.
- **Live Visual Analytics**: Interactive Chart.js time-series plots rendering historical actuals, 4-week forecasts, and safety stock reorder thresholds.
- **Enterprise Partner Grid**: Verified compatibility with Shopify Plus, Adobe Commerce (Magento), SAP S/4HANA, NetSuite, Akeneo PIM, AMD Instinct, and Evolus.
- **Interactive ROI Calculator**: Real-time sliders allowing retail executives to project capital recovery and margin improvements based on their annual GMV and stockout rates.
- **Executive PDF Export**: Formatted `@media print` style sheet enabling one-click generation of clean, executive-ready PDF audit reports without browser artifacts.

## Quick Start Guide

### 1. Prerequisites
- Python 3.10+ (tested on Python 3.11, 3.12, 3.13)
- Git
- (Optional) Docker

### 2. Installation
Clone the repository and set up a virtual environment:

```bash
git clone https://github.com/itsyourboydior/pulsecommerce-ai.git
cd pulsecommerce-ai

python -m venv .venv
# On Windows:
.venv\Scripts\activate
# On Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
```

### 3. Environment Configuration
Create your local `.env` file from the provided template:

```bash
cp .env.example .env
```

Configure your credentials inside `.env`:
```ini
# Option A: Direct Google AI Studio Key (Gemma 4)
GOOGLE_API_KEY=your_google_ai_studio_key_here

# Option B: AMD Developer Cloud / vLLM Endpoint
LLM_BASE_URL=https://your-amd-vllm-endpoint.amd.com/v1
LLM_API_KEY=your_amd_vllm_api_key_here
LLM_MODEL=gemma-4-26b-a4b-it

# Evolus Workspace (Optional)
EVOLUS_BASE_URL=https://api.evolus.ai/v1
EVOLUS_API_KEY=your_evolus_api_key_here
EVOLUS_WORKFLOW_ID=wf_inventory_promotion_agent
```

> **Security Guarantee**: The `.gitignore` file strictly excludes `.env`, `*.env`, and `.env.*`. Secrets will never be committed to source control.

---

### 4. Running the Pipeline

#### A. Generate Synthetic Retail Data & Run Benchmarks
```bash
cd src
# Generate multi-tenant sales & inventory data:
python synth_retail.py

# Run rolling-origin backtest benchmark:
python backtest.py

# Evaluate deterministic inventory policies:
python actions.py
```

#### B. Launch the Web Platform & Interactive Console
```bash
python web_demo.py
```
Open **`http://localhost:8080`** in your browser to access:
- The luxury editorial landing page and ROI calculator.
- The multi-tenant store switcher (Apex, Lumina, FreshHarvest).
- The interactive Chart.js demand visualization.
- Real-time Google Gemma 4 reasoning and PO drafting.
- Human-in-the-loop Approve/Reject controls with MCP transaction ledger logging.
- One-click Executive PDF Report export.

#### C. Run the End-to-End CLI Pipeline
```bash
python app.py --limit 3
```

## AMD Instinct GPU & vLLM Deployment

To serve Google Gemma 4 on dedicated AMD ROCm hardware (e.g., AMD Instinct MI300X):

```bash
docker run --rm -it --network=host \
  --device=/dev/kfd --device=/dev/dri \
  --group-add video \
  vllm/vllm-openai-rocm:latest \
  vllm serve google/gemma-4-31B-it \
    --max-model-len 32768 \
    --port 8000
```

Verify your deployment endpoint:
```bash
curl http://localhost:8000/v1/chat/completions \
  -H "Authorization: Bearer $LLM_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "google/gemma-4-31B-it", "messages": [{"role": "user", "content": "Ping"}]}'
```

## Security, Governance & Ethics

- **Zero Secret Exposure**: All credentials reside exclusively in uncommitted environment variables.
- **Deterministic Guardrails**: Google Gemma 4 is strictly prevented from altering mathematically calculated forecast numbers, order quantities, or pricing recommendations.
- **Human-in-the-Loop Safeguard**: Autonomous financial commitments are prohibited. Every purchase order or pricing markdown requires explicit, authenticated store manager sign-off before hitting the ERP ledger.
- **Cryptographic Auditability**: Each executed transaction is hashed with a verifiable reference code (`PO-...` or `PR-...`) recorded in `out/mcp_transactions.json`.
